## 唯一修正及原因

`3.xlsx / summary / barnyard` 的 `AX2:AX13` 原来分别引用 `beer_i!$AG$76`，与 stale_hops 重复。十二张卡逐一核对：R75 是 Stale hops，R89 是 Barnyard/horsey；对应响应公式分别在 AG76、AG90。派生副本改为 `beer_i!$AG$90`，不改原文件。

三种响应依赖验证中，U90、Y90、AE90 的临时标记使 barnyard 分别返回 1、3、6，stale_hops 始终为 0；测试后恢复空输入。全部卡片当前未填写，改前/改后缓存均为 0，**不形成任何真实评分标签**。

CSV 无任何“建议修正”列；没有数值变化、删行、删列、重编码、取反对数或整表标准化。CSV 不能保存工作簿公式，所以把修正副本连同前后对照合在同一个 XLSX，保持用户要求的三个交付文件。

## 为什么 NA 保留

用户的规则顺序是：先限制修正范围，再按已证实的缺失机制选择方法。结构性缺失填 0 加标记、随机缺失按尺度填中位数/最小值，均有适用前提；它们不是对所有 NA 的无条件修改授权。以下列都标为“需确认”，未同时满足范围和机制条件：

原文均为 NA，各 CSV 记录宽度完整，没有把解析失败冒充真实缺失。全列缺失不能证明结构性不存在，也没有可计算的中位数/最小值。八个化学列中的 60 格 NA 与校准表 0 对应，也不能据此认定这些 0 是真实未含有。保留未知满足“不猜测”的要求；本轮不需要再次请求数据范围例外。

作者论文 [Schreurs 等 (2024)](https://doi.org/10.1038/s41467-024-46346-0) 区分化学测量、逐评分员处理的专家评分和评论特征。作者 [Zenodo v3](https://zenodo.org/records/10653704) 的 `init_modeling.py` 提供均值插补/填 0 分支，但代码执行某项处理不能证明附件每个 NA 的机制，也没有补齐本题逐列尺度、检测限和完整处理血缘。未把该分支当作扩展清洗授权，未用新版作者数据覆盖比赛附件。原始方法文献与采用边界见 [文献索引](../../../.agents/skills/beer-data-cleaning/references/literature.md)。
